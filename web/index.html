Rolling Window Approach How the backtest avoids using future data
  • For each prediction month:
    • Select one global policy from earlier prediction months whose full 3-snapshot outcome window has already closed
    • Identify likely next practices for every eligible team using that month's policy
    • Validate against actual data (checks that month, the next observed snapshot, and the one after that)
  • Shows accuracy per month and overall average
  • Note: Validation checks up to 3 observed snapshots ahead to account for adoption timelines
  • Each recommendation blends three evidence sources — similarity (what comparable teams improved), the Practice Transition Model (observed transitions between consecutive improvement-bearing steps), and time-aware popularity (organization-wide improvement trends) — combined with weights chosen automatically per month. There are no user-adjustable model parameters.
  • Global policy options: The system evaluates 675 candidate policies: 3 peer counts × 3 similarity thresholds × 15 similarity/sequence/popularity weight combinations × 5 popularity recency weights. It selects one policy for the month; before any prior outcome window has closed, it uses the default bootstrap policy.
Strict temporal isolation enforced — recommendations never use future data ⓘ
